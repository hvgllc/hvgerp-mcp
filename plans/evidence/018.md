## Bước 2: Giới hạn và thu hồi

- Constructor nhận `maxEntries` tùy chọn, mặc định 1.000; `Number.isInteger` kết
  hợp kiểm tra dương từ chối số phân số, NaN, vô cực, 0 và số âm.
- Mỗi `set` lấy một mốc thời gian, quét entry hết hạn, xóa giá trị cũ cùng key.
  TTL bằng 0 hoặc âm không lưu giá trị mới và không đẩy key còn hạn ra khỏi
  cache.
- Khi đầy mới thu hồi key có lần ghi lâu nhất. Ghi cập nhật xóa rồi thêm key để
  chuyển về cuối thứ tự Map. Đọc không đổi thứ tự, đây là FIFO theo lần ghi gần
  nhất, không phải LRU.
- Giữ nguyên `get` và clone-on-read, `Cache` interface, delete, clear và prefix
  invalidation. Không thực thi clone-on-write của kế hoạch 019, không thêm
  timer.

```bash
deno test --config deno.nojsr.json --sloppy-imports --frozen --allow-all src/cache/
```

Exit 0: **32 passed, 0 failed**, gồm 16 test MemoryCache. Bao phủ cap 1, cap

prefix invalidation sau eviction.

## Bước 3: Số entry và hồi quy

Đã chạy cùng đoạn đo dưới đây bằng `node --input-type=module -e` trên source cũ
và source mới. `Reflect.construct(..., [100])` cho phép giữ nguyên fixture:
source cũ bỏ qua tham số vì chưa có constructor nhận cap, source mới áp dụng
cap 100.

```javascript
import { MemoryCache } from "./src/cache/memory.ts";
const originalNow = Date.now;
Date.now = () => 1000;
try {
  const cache = Reflect.construct(MemoryCache, [100]);
  let peak = 0;
  for (let i = 0; i < 10000; i++) {
    cache.set(`key:${i}`, i, 1000);
    peak = Math.max(peak, Reflect.get(cache, "store").size);
  }
  console.log(JSON.stringify({
    writes: 10000,
    requestedCap: 100,
    peak,
    retained: Reflect.get(cache, "store").size,
    newest: cache.get("key:9999"),
  }));
  const expired = new MemoryCache();
  for (let i = 0; i < 1001; i++) expired.set(`expired:${i}`, i, 10);
  Date.now = () => 1010;
  expired.set("fresh", 42, 1000);
  console.log(JSON.stringify({
    expiredFixtureRetained: Reflect.get(expired, "store").size,
  }));
} finally {
  Date.now = originalNow;
}
```

| Phép đo cùng fixture                           | Trước sửa | Sau sửa |
| ---------------------------------------------- | --------: | ------: |
| Peak entry qua 10.000 lần ghi, cap yêu cầu 100 |    10.000 |     100 |
| Entry giữ lại cuối 10.000 lần ghi              |    10.000 |     100 |
| Giá trị đọc ở key mới nhất                     |     9.999 |   9.999 |
| Entry sau 1.001 key hết hạn và một lần ghi mới |     1.002 |       1 |

Regression Deno kiểm số entry không vượt 100 sau **từng lần ghi**, key 9899 đã
thu hồi, key 9900 và 9999 vẫn đọc đúng. Đây chỉ là phép đo số entry được giữ,
không phải benchmark thời gian hay bằng chứng về latency.

## Giới hạn và bàn giao

- Mỗi lần ghi quét tối đa số entry trong cap, chi phí O(maxEntries). Đây không
  phải giới hạn byte của giá trị hay toàn bộ bộ nhớ tiến trình. Không có tải đo
  production hoặc số liệu hit rate; không tuyên bố cải thiện latency.
- Bốn integration test bị bỏ qua theo cấu hình vốn có, không gọi ERPNext thật.
  Không chỉnh test để giảm gate, không có tài nguyên rò được Deno báo cáo.
- npm cảnh báo về install scripts chưa được allowScripts, nhưng các build đều
  exit 0. Không duyệt thêm install script hoặc sửa manifest để bỏ cảnh báo.
- Lần thử đo source trung gian bằng Node gặp `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`
  do parameter property. Đã dùng field và assignment constructor tường minh;
  chạy lại cùng phép đo đạt exit 0, rồi xác minh bundle Node và full suite.
- Đã tự đọc toàn bộ diff source. Không sửa source UI, schema tool, dependency,
  credential, version hoặc môi trường production. Build chỉ tạo hiện vật
  ignored.
- Skill improve execute yêu cầu tách xác minh độc lập khỏi executor. Đây là bằng
  chứng thực thi local, chưa phải tự phê duyệt; parent tiếp tục review, cập nhật
