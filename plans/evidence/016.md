## Checklist Browser giao parent

Sau tích hợp PR015, build lại UI và mở host 007 theo hướng dẫn hiện có:

```text
http://127.0.0.1:5178/testing/host.html?viewer=kanban-viewer&scenario=board-race
```

Mỗi response deferred cần release trong timeout RPC 10 giây. Reload giữa các ca
để fixture trở về ban đầu. Giữ trace host và ảnh board sau từng mốc quan trọng.

1. Board A: tạo read bằng focus thật, giữ read; bấm Start thẻ A1; release move
   thành công rồi read cũ. A1 phải còn Working, xuất hiện đúng một fresh read.
   Release fresh read và kiểm pending kết thúc. Lặp với read cũ trả giữa move.
2. Queue: khi move A1 còn held, bấm Start A2. Chỉ move đầu đang chờ; release lần
   lượt, sau cùng mới có một read. Lặp ca reject move thứ hai: A1 Working, A2
   Open, lỗi hiện đúng, stale read không rollback A1.
3. Khi read A đang held, bấm Gửi board B. Cả hai đều task-board nhưng project
   khác. Release read A: không xuất hiện thẻ A; read tiếp theo dùng PROJECT-B.
4. Bấm Gửi trang 0, tạo read held; bấm Gửi trang 50; release read cũ. Chỉ còn
   TASK-PAGED-51/52, offset 50, tổng 52; read tiếp theo giữ offset 50, limit 50.
5. Dùng chuyển tab thật để hidden rồi focus lại. Khi hidden, pending không bị
   mất; focus tạo một read khi idle. Không sửa `document.visibilityState` để
   thay thế ca này. Dùng drag thật để giữ gate, release stale read hoặc kết thúc
   write trong khi drag; drag end phải drain đúng một read.
6. Giữ read board, mở detail A1 rồi release doc_get. Thực hiện save, assign,
   unassign từng ca; old board read không hydrate đè. Với save, release update
   thành công rồi reject doc_get: vẫn báo đã lưu, board revalidate. Lặp đổi
   board B trước khi write/readback trả: modal cũ đóng, B không nhận detail A.
7. Reject read: giữ board cuối tốt, không xuất hiện vòng request liên tục. Focus
   thật hoặc interval kế tiếp retry; write mới hoàn tất vẫn có revalidation.

Các fixture date/malformed/detail hiện có giữ nguyên. Không coi Node VM kiểm
visibility boolean là đã hoàn tất ca tab/drag trong Browser.
